How Beginners Build a Weather App With JavaScript

Programming · 17 November 2026 · 8 min read

Build a weather app with JavaScript as a beginner. This guide covers the free API key, fetch, layout, city search, and geolocation.

You build a weather app with JavaScript by asking a free weather service for live data and showing it on one page. You learn how to build a weather app with JavaScript for beginners by adding one small feature at a time. You need only a text editor and a browser.

Get a Free Weather Key and Set Up Your Project

You start with an OpenWeatherMap API free key for beginners by opening the OpenWeatherMap site and creating an account. You learn how to build a weather app with JavaScript for beginners by keeping the key in one safe place in your notes. You create one folder with three files for the page, the style, and the script.

A free key works because the weather service trusts your app and it sends live data back to your page. You wait a short time after you create the key because new keys need a few minutes to answer. You test the key with one simple link in your browser and you check that real weather data shows on the screen.

You build a weather app HTML CSS layout for beginners by adding a search box, a button, and a card that shows the weather. You place the city name at the top and the temperature below it in large text. You add small lines for wind and humidity under the temperature.

A clean layout works because the reader finds the temperature in one glance and the details stay in a neat order. You keep the card narrow so it reads well on a phone. You test the page after each small change and you fix the spacing while the code stays fresh in your mind.

Fetch Live Weather Data With JavaScript

You use the JavaScript fetch API to get weather data by writing one short function that sends your key and the city name to the service. You learn how to build a weather app with JavaScript for beginners by testing the fetch with one city first. You read the answer and you pick the temperature and the city name from it.

Fetch works because your page asks the service for fresh data each time the user types a city. You keep the function short so you can read it in one glance and you fix a mistake fast when the data fails to load. You show a short loading message while the app waits so the user knows it still works.

Show the Weather and Handle City Search

You show the weather on the card by taking the temperature, the city name, and the weather condition from the data. You write each value into the matching line with one short line of code. You round the temperature to a whole number so the card reads clean and clear.

City search works because the user types a name and the app asks the service for that city at once. You clear the old weather from the card before you show the new result so the user never sees a stale number. You keep the last city in the box so the user can fix a spelling mistake fast.

You add a weather app city search and geolocation for beginners by asking the browser for the user location with one short call. You send the latitude and longitude to the weather service instead of a city name. You show the weather for that place and you keep the city search as a backup.

Geolocation works because it removes the typing step and it gives the user the weather for their own city at once. You handle the case when the user says no and you show the search box instead. You test the app with the location off and you check that the search still works well.
